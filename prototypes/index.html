Trade Pipeline
Dashboard exploration

Cuatro enfoques conceptualmente distintos para operar el pipeline de procesamiento de trades financieros. Cada prototipo cubre las 9 pantallas (Overview, Run, Data Sources con Kafka, Business, Quality, Validation Rules, Audit, History, Settings) y es interactivo end-to-end. Cada uno soporta light + dark mode y un widget flotante abajo-derecha permite saltar entre prototipos.

When to choose what

user × context fit

A · TRADESYS works best for…

  • Power users que ya tienen lenguaje técnico interno (run_id, RV-XX, notional)
  • Trading floor donde el monitor está siempre encendido y la densidad importa
  • Debug y forensics: muchos IDs, JSON crudo, paneles compactos
  • Equipos que valoran "feel pro" sobre "feel friendly"
density:high · learnability:medium · onboarding:low · pro-feel:high

B · Pipely works best for…

  • Usuarios menos técnicos (compliance, ops) que necesitan acceder ocasionalmente
  • Demo y stakeholders externos donde la primera impresión importa
  • Sesiones largas — el contraste bajo y el spacing reducen fatiga
  • Equipos construyendo su lenguaje y que quieren un UI más explorable
density:medium · learnability:high · onboarding:high · pro-feel:medium

C · Atlas works best for…

  • Analistas que pasan tiempo explorando charts — la lectura es el trabajo
  • Reportes que se imprimen o se comparten como documentos
  • Cuando la audiencia consume datos visualmente más que tablularmente
  • Comunicación con stakeholders ejecutivos — feel editorial / lab
density:medium · learnability:medium · onboarding:medium · pro-feel:high

D · Sentinel works best for…

  • Bancos tradicionales, regulación pesada, audit trail prioridad #1
  • Compliance officers que firman reportes — UI sugiere "documento oficial"
  • Organizaciones con cultura conservadora; lenguaje formal y respetuoso
  • Cuando "soberbia" o "novedad" son anti-features — confianza > diferenciación
density:medium · learnability:high · onboarding:high · pro-feel:high
